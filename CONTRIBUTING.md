# Contributing to SignalHub Community Intelligence

Thank you for helping improve vulnerability intelligence.

## Where to contribute

Use the [SignalHub web platform](https://signalhub.vulnhero.com) for vulnerability evidence, affected-version updates, PoC references and remediation information. This GitHub repository is for documentation, public schemas, and approved public datasets; it is **not** a direct intake for confidential vulnerability reports.

## Evidence checklist

A useful contribution includes:
1. CVE identifier, or an explicit reason why no CVE is assigned.
2. A precise, falsifiable claim (e.g. affected version range, public PoC exists, fix available).
3. Original, accessible reference URLs and dates.
4. Product/vendor and version context.
5. What was directly observed versus inferred.
6. Disclosure or sharing restrictions, where applicable.

No credentials, private customer data, embargoed vulnerability details, unauthorized test results, or weaponized exploit payloads.

## Review and corrections

A submission can be pending, accepted, rejected, or require changes. Review should examine source integrity, attribution, independent corroboration where available, and whether the evidence actually supports the claim. Acceptance of a reference does not assert live exploitation. Corrections and withdrawals should retain review history.

## GitHub contributions

For public documentation and schema changes: open an Issue describing the change, then submit a Pull Request against `main`. Keep changes narrowly scoped and include references or tests where relevant. Public issues must not contain secrets or non-public vulnerabilities.

## Recognition

Attribution and reputation are based on meaningful, reviewed contributions rather than message volume. See [Attribution Policy](docs/attribution-policy.md).
